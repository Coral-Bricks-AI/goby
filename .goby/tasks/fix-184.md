Fix GitHub issue #184 in this repository: `cleaners/cleaner.sh` aborts with
`line 137: THINKING: unbound variable` when it is run directly (not through
`entrypoint.sh`, which sources `defaults.env` and sets `THINKING` first), because
`cleaner.sh` is run under `set -euo pipefail` and reads `$THINKING` with no fallback
and no default of its own.

Read the issue body with `gh issue view 184` for the full repro and the exact line.

Important constraint the issue's own illustrative fix does not satisfy:
`cleaners/test_entrypoint.py::test_the_thinking_level_is_the_image_s_default_not_the_dependency_s`
asserts the literal `--thinking "$THINKING"` is still present in `cleaner.sh` — do not
change that argument. Instead give `THINKING` a default *before* it is read, the same
way `cleaners/defaults.env:11` already does it for the entrypoint path:

```sh
: "${THINKING:=high}"
```

Add that line (or read it, read-only, from `cleaners/defaults.env` — you may read any
file for context even though your edits are scoped to `cleaners/cleaner.sh`) near the
top of `cleaner.sh`, before `--thinking "$THINKING"` is built into `PI_ARGS`, so a
direct invocation with no `THINKING` in its environment defaults to `high` and reaches
`pi` instead of aborting under `set -u`. Do not change anything else in the file, and
run `python3 -m pytest -q cleaners/test_entrypoint.py` yourself before calling
`report_done` to confirm nothing you changed breaks a pinned test. When you are done,
call `report_done` with a short summary of what you changed and why.
