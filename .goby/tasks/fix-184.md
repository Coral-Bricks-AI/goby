Fix GitHub issue #184 in this repository: `cleaners/cleaner.sh` aborts with
`line 137: THINKING: unbound variable` when it is run directly (not through
`entrypoint.sh`, which sources `defaults.env` and sets `THINKING` first), because
`cleaner.sh` is run under `set -euo pipefail` and reads `$THINKING` with no fallback
and no default of its own.

Read the issue body with `gh issue view 184` for the full repro and the exact line.
The fix shown in the issue's own "and the defect goes away when the blamed line is
changed" section is: give `--thinking "$THINKING"` a fallback, i.e.
`--thinking "${THINKING:-high}"`, so a direct invocation of `cleaner.sh` with no
`THINKING` in its environment renders the prompt and reaches `pi` instead of aborting
before it starts.

Make exactly that change (or an equivalent one that gives `THINKING` the same `high`
default without requiring the caller to source `defaults.env`). Do not change anything
else in the file. When you are done, call `report_done` with a short summary of what
you changed and why.
